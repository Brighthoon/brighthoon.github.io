[2026-04-14] YOLO26 모델(seg, pose) 테스트 및 클라이밍 홀드 커스텀 학습

2026.04.14
5 min read

📝 2026-04-14 개발 기록

🔄 이전 작업 리뷰

🏗️ 진행한 작업 및 트러블슈팅

1. 영상 업로드 및 비동기 파이프라인 설계

  • Presigned URL 기반 업로드 (Storage: AWS S3)
    • 사유: API 서버를 거칠 경우 발생하는 이중 트래픽(In/Out) 및 서버 리소스(메모리/스레드) 점유 문제를 방지. "Front-stage의 가벼운 I/O" 원칙 준수.
    • 흐름:
      1. 사용자가 메타데이터와 함께 업로드 요청 ➡️ API 서버: DB 레코드 생성(status: PENDING) 및 Presigned URL 반환.
      2. 클라이언트 ➡️ AWS S3로 직접 업로드 (API 서버 우회).
  • 이벤트 기반 업로드 완료 감지 (AWS Lambda + Webhook)
    • 사유: S3 업로드 성공 시점을 즉각 파악하여 후속 AI 분석을 시작하기 위함. Polling 방식보다 리소스 효율적임.
    • 구현: S3 Object Created 이벤트 발생 ➡️ AWS Lambda 호출 ➡️ API 서버 Webhook 엔드포인트 호출 ➡️ DB 상태 변경(PENDING -> PROCESSING) 및 작업 큐 등록.
  • 메시지 브로커 선정: Redis/SQS (Task Queue) vs Kafka
    • 결정: Redis/SQS 사용.
    • 사유: 본 시스템은 이벤트를 영구 보존하며 재재생(Replay)해야 하는 'Streaming' 요건보다, 각 워커에게 작업을 효율적으로 분배하고 완료 후 삭제하는 'Task Queue' 요건이 지배적임. Kafka 도입은 현재 단계에서 오버엔지니어링으로 판단하여 운영 효율성이 높은 도구 선택.
  • 고아 데이터(Orphan Data) 처리
    • 사유: URL만 발급받고 실제 업로드를 실패한 불일치 데이터 정리 필요.
    • 해결: Celery Beat(스케줄러)를 활용하여 생성된 지 24시간이 지난 PENDING 레코드 및 관련 S3 데이터 자동 삭제.

2. 시스템 모니터링 및 성능 지표 설계

  • 관찰 지표 (Observability):
    • Business: E2E 처리 시간 (업로드 완료 ~ AI 추론 완료), 상태별 데이터 분포.
    • Infrastructure: Queue Depth (Celery 큐 적체량 - Scale-out의 기준), GPU Utilization (Triton 서버 부하).
    • Storage: 업로드 실패율 (Orphan Data 삭제 건수 추적).

3. 파트별 구현 체크리스트

Frontend (Next.js)

  • 영상 업로드 UI: 메타데이터 입력 폼 및 파일 선택기 구현.
  • Presigned URL 연동: API 서버로부터 URL을 받아 S3로 직접 PUT 요청 수행.
  • 업로드 프로그레스 바: 대용량 파일 전송 상태를 사용자에게 실시간으로 시각화.
  • 상태 모니터링 페이지: 분석 단계(PENDING -> PROCESSING -> COMPLETED)를 실시간으로 확인할 수 있는 대시보드.

Backend (FastAPI & Celery)

  • Presigned URL 발급 API: boto3를 활용한 S3 권한 부여 및 DB 레코드 초기화.
  • S3 Webhook 엔드포인트: Lambda의 완료 신호를 수신하여 Celery 작업 트리거.
  • Celery 분석 Task:
    • 썸네일/배경 이미지 추출 로직.
    • ~~Triton Server gRPC 통신 및 결과 후처리.
  • Garbage Collector (Celery Beat): 24시간 초과 PENDING 데이터 자동 정리 로직.

Infrastructure (Terraform)

  • S3 Buckets: Raw 데이터와 가공 데이터(Assets) 저장을 위한 버킷 생성.
  • IAM Policy: 서비스별(Lambda, API, Worker) 최소 권한 원칙 기반의 정책 설계.
  • Lambda & Event Notification: S3 업로드 이벤트를 API 서버로 전달하는 서버리스 함수 구축.
  • Container Registry (ECR): 각 마이크로서비스 이미지 관리를 위한 저장소 구성.
