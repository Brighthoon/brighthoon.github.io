1. 메타데이터 선택(Optional) 입력 처리

  • 개요: 사용자가 비디오 업로드 시 입력하는 부가 정보(암장 이름, 난이도, 성공 여부)를 필수가 아닌 선택 사항으로 변경하여 UX 개선.
  • Frontend (clcam-frontend):
    • 입력 폼의 기본값을 제거하고 placeholder로 대체하여 미입력 상태 허용.
    • 성공 여부(isSuccess) 상태를 boolean | null (3-state)로 변경하고, UI를 Select Box(미선택, 성공, 실패)로 교체.
    • useFileUploadPipeline 훅 및 UploadMetaData 인터페이스를 수정하여 값이 없는 경우 null을 백엔드로 전송하도록 로직 변경.
  • Backend (clcam-backend):
    • DB 모델(app/models/climbing.py)에서 gym_name과 is_success 컬럼을 nullable=True로 수정.
    • Pydantic 스키마(app/schemas/climbing.py)의 UploadInitRequest, ClimbingProblemResponse에서 관련 필드를 Optional로 변경.

2. S3 Presigned URL CORS (Preflight) 에러 해결

  • 문제: 프론트엔드에서 발급받은 S3 Presigned URL로 직접 업로드(PUT) 시 브라우저에서 CORS 에러 발생.

[!abstract] Issue: S3 Presigned URL CORS (Preflight) 에러

  • 현상: No 'Access-Control-Allow-Origin' header is present 에러 발생. S3 버킷에 CORS 설정을 했음에도 불구하고 브라우저에서만 발생.
  • 원인: AWS S3의 글로벌 엔드포인트 사용 시 발생하는 307 Redirect 동작 때문. 브라우저의 Preflight(OPTIONS) 요청은 보안상 Redirect를 따라가지 않으므로, S3가 내려주는 실제 CORS 헤더를 확인하지 못함.
  • 해결: 백엔드(app/services/s3.py)에서 S3 Client 초기화 시 리전이 명시된 Regional Endpoint를 강제하고, addressing_style을 virtual로 설정하여 리다이렉트 발생을 원천 차단.
  • 참조: boto3.client(..., endpoint_url=f"https://s3.{settings.AWS_REGION}.amazonaws.com", config=Config(s3={'addressing_style': 'virtual'}))

💡 새롭게 알게 된 것 / 메모

  • S3 직접 업로드 아키텍처 필수 구성 요소:
    1. 인프라 (Terraform): S3 Bucket CORS Rule 설정 (AllowedOrigins, Methods, Headers 등).
    2. 백엔드 (Python/FastAPI): Presigned URL 생성 시 Regional Endpoint를 명시하여 307 Redirect 방지.
  • 브라우저 환경에서의 Preflight 정책은 서버 간 통신(Python, curl 등)보다 훨씬 엄격하므로 리다이렉트 여부를 반드시 체크해야 함.
