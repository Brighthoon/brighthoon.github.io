🔄 이전 작업 리뷰

  • 비디오 업로드 로직 기초 구현 및 S3 연동 테스트 완료

🏗️ 진행한 작업 및 트러블슈팅

1. API 설계 개편: RPC에서 RESTful로의 전환

기존의 행위 중심 API(POST /upload/init)를 자원(Problem) 중심으로 전면 개편했습니다.

✨ 구현한 내용:

  • 리소스 생성(POST /api/problems), 정보 수정(PATCH), 삭제(DELETE /api/problems/{id}) API 엔드포인트 구현.
  • S3 객체 삭제 로직(delete_s3_object)을 추가하고 DELETE 엔드포인트와 연동.
  • 비디오 파이프라인을 트리거하기 위한 전용 Action 엔드포인트(POST /api/problems/{problem_id}/upload-complete) 신설.

🤔 설계 근거 (단일 PATCH 엔드포인트 통합을 배제한 이유):

  • 모든 상태 변경을 PATCH /problems/{id}로 통합하면, 악의적인 클라이언트가 Payload를 조작해 비즈니스 로직(AI 파이프라인 등)을 우회하는 Mass Assignment(대량 할당) 취약점이 발생할 수 있습니다.
  • 일반적인 데이터 수정(PATCH)과 S3 검증 및 메시지 큐 트리거 등 무거운 사이드 이펙트를 동반하는 상태 전이(POST .../upload-complete)를 엄격하게 분리하여 API의 응집도와 보안성을 높였습니다.

2. AWS 이벤트 주도형(Event-Driven) 인프라 및 서버리스 워커 구축

업로드된 영상에 대한 썸네일 추출 및 AI 분석 파이프라인을 구축했습니다.

✨ 구현한 내용:

  • Terraform 기반 인프라 배포: S3 버킷에 영상 업로드 시 SNS로 알림을 보내고, 이를 두 개의 SQS 큐(Thumbnail, DL Pose)로 복제(Fan-out)하는 구조(events.tf) 구축.
  • 서버리스 썸네일 워커 개발 (clcam-services/thumbnail): SQS를 트리거로 동작하며, Python 및 OpenCV를 활용해 영상의 프레임을 추출하는 AWS Lambda 함수 개발.
  • 버전 제어 및 동적 매핑: 환경 변수(THUMBNAIL_VERSIONS)와 딕셔너리 기반 동적 매핑 로직을 도입해, 재배포 없이 추출 알고리즘 버전을 제어.
  • 개별 Dockerfile을 작성하여 Lambda를 AWS ECR 컨테이너 이미지로 패키징 및 배포(lambda_thumbnail.tf).

🤔 설계 근거:

  • SNS + SQS Fan-out 패턴: 가벼운 작업(썸네일)과 무거운 작업(GPU 기반 AI 분석)이 상호 간섭 없이 비동기적으로 병렬 실행되며, 트래픽 폭주 시 SQS 대기열을 통해 안정적인 오토 스케일링을 지원합니다.
  • Monorepo 기반 서비스 격리: 메인 API 서버와 각 AI 워커 간의 라이브러리 충돌(OpenCV, PyTorch 등)을 방지하기 위해 마이크로서비스 구조로 종속성을 완벽히 분리했습니다.

3. 어노테이션(Action Spotting) 기능 풀스택 구현

향후 AI 모델 학습 데이터 구축을 위해, 관리자가 비디오의 특정 구간(Interval)을 효율적으로 지정할 수 있는 기능을 구현했습니다.

✨ 구현한 내용:

  • 프론트엔드 (clcam-frontend):
    • shadcn/ui의 Checkbox, Slider 컴포넌트 연동.
    • 관리자 목록 페이지(AdminProblemList)에서 다중 선택 체크박스와 Floating Action Bar를 구현하고, 선택된 ID를 URL 파라미터 큐(?queue=...)로 전달.
    • 어노테이션 작업 페이지(AdminProblemAnnotate)에 비디오 플레이어와 커스텀 듀얼 레인지 슬라이더(Start/End Zone) 구현. 슬라이더 드래그 시 비디오 프레임이 실시간으로 동기화(Seeking)되도록 처리.
    • 로컬 개발 환경에서 422 에러 방지를 위해 Axios Interceptor를 수정해 x-worker-token을 자동 주입.
    • [Save & Next] 버튼 클릭 시 큐의 다음 ID로 즉시 라우팅(router.push)되는 연속 작업 흐름 구현.
  • 백엔드 (clcam-backend):
    • S3 generate_presigned_get_url 함수 신설 및 Orval용 VideoUrlResponse Pydantic 모델 명시.
    • 프론트엔드 브라우저 캐싱(Disk Cache)을 유도하기 위해 S3 Presigned URL을 50분간 백엔드 메모리에 캐싱하는 신규 엔드포인트(GET /problems/{id}/video-url) 구현.

🤔 설계 근거:

  • 작업 결과 DB 스키마 분리: 구간 정보를 메인 ClimbingProblem 테이블의 정적 컬럼에 추가하지 않고, ProblemJob 테이블의 result_data (JSONB) 필드에 적재했습니다. 이는 "수동 태깅", "v1 모델 결과" 등 버전을 구분하여 데이터 리니지(Lineage) 추적과 성능 비교를 가능하게 합니다.
  • 비용 절감 최적화: 프라이빗 S3 영상을 매번 API로 호출하면 데이터 전송 비용이 낭비되므로, 백엔드 인메모리 캐싱을 통해 브라우저 캐싱을 우회 지원함으로써 비용을 최적화했습니다.
Issue: 백엔드 AWS SSO 인증 (Boto3) 실패 에러
  • 현상: 로컬 머신에서 aws sso login을 완료했음에도 FastAPI 앱(boto3)에서 botocore.exceptions.LoginRefreshRequired 에러 발생.
  • 원인: 백엔드 프로세스가 default 프로필 대신 사용자가 로그인한 특정 SSO 프로필을 바라보지 못해서 발생한 인증 세션 갱신 실패.
  • 해결: 로컬 환경 변수(.env)에 명시적으로 AWS_PROFILE=<프로필명>을 지정하여 올바른 토큰 캐시를 참조하도록 수정.
Issue: AWS Lambda ECR 이미지 호환성 에러
  • 현상: 테라폼으로 Lambda 배포 시 OCI 이미지 규격 미지원 에러(InvalidParameterValueException) 발생.
  • 원인: Docker Buildx로 빌드 시 최신 메타데이터(Provenance Attestations)가 자동으로 추가되는데, AWS Lambda가 이를 인식하지 못함.
  • 해결: docker build --provenance=false 플래그를 추가하여 문제의 메타데이터 레이어를 강제로 제외.
Issue: Lambda 임시 저장소(/tmp) 용량 누수 위험
  • 현상: Lambda 'Warm Start' 시 컨테이너 재사용으로 인해 잔여 파일이 쌓여 No space left on device 에러 발생 우려.
  • 원인 및 해결: 컨테이너의 상태를 항상 초기화(Idempotent)하도록, 썸네일 추출 로직의 finally 블록에서 처리 성공 여부와 관계없이 다운로드한 .mp4 및 .jpg 파일을 명시적으로 os.remove() 하도록 수정.

💡 새롭게 알게 된 것 / 메모

  • SQS와 SNS를 결합한 Fan-out 패턴은 파이프라인의 병목을 해결할 뿐만 아니라, 성격이 다른 워커(가벼운 추출 vs 무거운 GPU 분석) 간의 장애 격리(Fault Isolation)에도 매우 유리합니다.
  • RDBMS 환경에서도 생성 주체(Human vs AI)와 시점이 다변화되는 메타데이터의 경우, 정적 컬럼을 고집하기보다 JSONB 형태의 로그(Job) 테이블로 분리하는 것이 유연성에 훨씬 유리함을 깨달았습니다.
