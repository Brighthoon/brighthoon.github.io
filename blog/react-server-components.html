React Server Components 완벽 가이드

RSC(React Server Components)는 서버와 클라이언트를 아우르는 새로운 패러다임의 아키텍처입니다. 기존의 클라이언트 렌더링(CSR)이나 단순한 서버 사이드 렌더링(SSR)을 넘어서, 컴포넌트 단위로 렌더링 위치를 결정할 수 있게 해줍니다.

1. RSC의 핵심 개념

  • 서버 전용 렌더링: 클라이언트로 자바스크립트 번들을 전송하지 않고, 서버에서 데이터를 패칭하고 HTML만 내려줍니다.
  • 제로 번들 사이즈: 무거운 외부 라이브러리(예: 마크다운 파서, 날짜 포맷터)를 서버 컴포넌트 내부에서만 사용하면 클라이언트 번들에 포함되지 않습니다.

2. 서버 컴포넌트 vs 클라이언트 컴포넌트

특징서버 컴포넌트 (Server Component)클라이언트 컴포넌트 (Client Component)
JS 번들클라이언트로 전송되지 않음클라이언트로 전송됨 (Hydration 필요)
상태 (State)useState, useEffect 사용 불가사용 가능
API브라우저 API 사용 불가window, document 접근 가능
명시기본값 (아무것도 안 쓰면 서버)파일 최상단에 "use client" 명시

언제 무엇을 써야 할까?

  • 서버 컴포넌트: 데이터베이스 접근, 백엔드 API 호출, 정적 UI 렌더링, 무거운 라이브러리 연산
  • 클라이언트 컴포넌트: 사용자 상호작용 (버튼 클릭, 폼 입력), 상태 관리, 브라우저 전용 API 사용

3. 코드 예시

// app/page.tsx (서버 컴포넌트)
import { db } from '@/lib/db';

export default async function Page() {
  const users = await db.user.findMany(); // 서버에서 DB 직접 접근 가능

  return (
    <main>
      <h1>사용자 목록</h1>
      <ul>
        {users.map(user => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </main>
  );
}

RSC는 아직 학습 곡선이 있지만, 프론트엔드 성능 최적화의 미래임에는 틀림없습니다.
