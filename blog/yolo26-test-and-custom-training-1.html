[2026-04-10] YOLO26 모델(seg, pose) 테스트 및 클라이밍 홀드 커스텀 학습

2026.04.10
5 min read

📝 2026-04-10 개발 기록

🏗️ 진행한 작업 및 트러블슈팅

1. YOLO26 모델(n, n-seg, n-pose) 테스트

  • 진행 내용:
    • 최신 모델이면서 Segmentation과 Pose Estimation이 모두 가능하여 YOLO26을 도입하기로 결정함.
    • yolo26n, yolo26n-seg, yolo26n-pose 모델들을 이용하여 기본적인 탐지 및 예측 테스트 진행.
    • 클라이밍 홀드 감지 여부를 확인하기 위해 yolo26n-seg를 사용해 봄 (seg 모델의 경우 bbox와 mask 결과를 함께 반환하므로 일반 모델 대신 seg 모델 채택).
  • 결과 및 특이사항:
    • 사전 학습된 기본 모델로는 클라이밍 홀드를 탐지하지 못함을 확인하여, 커스텀 데이터 학습으로 방향을 전환함.

2. 클라이밍 홀드 탐지를 위한 커스텀 모델 학습 (yolo26m-seg)

  • 진행 내용:
    • Roboflow에서 클라이밍 홀드 Segmentation 데이터를 확보하여 다운로드.
    • 확보한 데이터를 바탕으로 yolo26m-seg 모델 학습 진행 중.

3. 테스트 및 학습용 Docker 환경 구축

  • 진행 내용:
    • 테스트와 모델 학습을 일관된 환경에서 진행하기 위해 전용 Dockerfile을 작성하고 컨테이너 환경을 구축함.
FROM nvcr.io/nvidia/tritonserver:26.03-py3

# Set environment variables
ENV DEBIAN_FRONTEND=noninteractive
ENV PYTHONUNBUFFERED=1

# Install system dependencies
RUN apt-get update && apt-get install -y \
    python3-pip \
    libgl1 \
    libglib2.0-0 \
    libsm6 \
    libxext6 \
    libxrender-dev \
    pkg-config \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Copy requirements and install
COPY requirements.txt /tmp/requirements.txt
RUN pip3 install --no-cache-dir -r /tmp/requirements.txt

# Set working directory
WORKDIR /workspace

# Expose ports:
# 8000-8002: Triton
# 8888: Jupyter
EXPOSE 8000 8001 8002 8888

# Create a startup script to run both Triton and Jupyter
RUN printf '#!/bin/bash\n\
tritonserver --model-repository=/models --log-verbose=1 &\n\
jupyter lab --ip=0.0.0.0 --port=8888 --no-browser --allow-root ' > /usr/local/bin/start.sh && \
    chmod +x /usr/local/bin/start.sh

# Set the default command
CMD ["/usr/local/bin/start.sh"]
Troubleshooting
  • Issue (문제): 학습 진행 중 Dataloader의 worker 수를 2 이상으로 설정했을 때, GPU 가용율(Utilization)이 0%에 머물며 학습이 전혀 진행되지 않는(멈추는) 현상 발생.
  • Cause (원인): Docker 컨테이너 내부의 공유 메모리(Shared Memory) 크기가 부족하여 멀티 프로세싱(Multi-processing) 데이터 로딩 시 병목/데드락이 발생함.
  • Solution (해결): docker run 실행 시 --shm-size (예: --shm-size=8g 등) 옵션을 추가하여 컨테이너에 할당되는 공유 메모리 크기를 늘려주어 문제 해결.
  • Reference: Docker Shared Memory Issue, PyTorch Dataloader Workers

💡 새롭게 알게 된 것 / 메모

  • YOLO26 모델 선정 이유: 현시점 최신 모델 구조이며 하나의 파이프라인에서 Seg, Pose를 모두 처리할 수 있어 확장성에 유리함.
  • Seg 모델 활용: 객체 탐지 시 seg 모델을 사용하면 마스크(Mask)뿐만 아니라 바운딩 박스(bbox) 정보도 한 번에 얻을 수 있어 일반 객체 탐지용으로도 범용성 있게 활용 가능함.
