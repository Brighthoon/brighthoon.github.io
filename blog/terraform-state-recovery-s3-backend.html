Terraform State 복구하기: S3 Backend 마이그레이션 실수 대처법

2026.04.20
5 min read

문제 발생: S3 Backend 추가 중 "No"를 선택하다

다른 환경에서 Terraform 작업을 이어가기 위해 로컬에서 관리되던 state를 S3 backend로 마이그레이션하는 작업을 진행했습니다. backend "s3" 블록을 추가하고 terraform init을 실행하면 다음과 같은 프롬프트가 나타납니다.

Do you want to copy existing state to the new backend?
  Pre-existing state was found while migrating the previous "local" backend to the
  newly configured "s3" backend. No existing state was found in the newly
  configured "s3" backend. Do you want to copy this state to the new "s3"
  backend? Enter "yes" to copy and "no" to start with an empty state.

여기서 실수로 **"no"**를 입력하게 되면, 새로 구성된 S3 백엔드에는 아무런 상태 정보가 복사되지 않고 완전히 비어있는 상태로 초기화됩니다.

이후 terraform plan을 실행하면, Terraform은 S3에 상태 파일이 없으므로 현재 생성되어 있는 인프라를 전혀 인식하지 못하고 모든 인프라를 새로 추가(add)하겠다는 계획을 출력하게 되어 매우 당황스러운 상황이 연출됩니다.

시도: terraform.tfstate.backup 이름 변경하기

이러한 상황에서 가장 먼저 떠오르는 생각은 로컬에 남아있는 terraform.tfstate.backup 파일을 terraform.tfstate로 이름을 변경해서 복구하려는 시도입니다.

하지만 이미 terraform init을 통해 백엔드가 S3로 변경되었기 때문에, 로컬 디렉토리에 있는 .tfstate 파일을 직접 수정하거나 이름을 변경하는 것만으로는 Terraform이 기존 인프라를 다시 인식하지 못합니다. Terraform은 이제 로컬 파일이 아닌 구성된 원격 저장소(S3)를 바라보고 있기 때문입니다.

해결책: terraform state push

결국 이 문제는 terraform state push 명령어를 통해 해결할 수 있습니다. 로컬에 안전하게 남아있는 백업 파일을 이용해 원격 저장소의 상태를 원상 복구하는 것입니다.

terraform state push terraform.tfstate.backup

(또는 이름을 바꾼 terraform.tfstate 경로를 지정)

terraform state push는 어떻게 동작하는 걸까?

이 명령어를 사용하면서 "S3에 푸시해서 정상적으로 인식된 것인지, 아니면 백엔드에 있는 것을 로컬에 푸시해서 정상적으로 인식된 것인지" 헷갈릴 수 있습니다.

정답은 **"로컬에 있는 백업 State 파일을 S3(현재 설정된 Backend)로 덮어쓰기(Push) 한 것"**입니다.

  1. terraform init을 거쳐 현재 Terraform의 백엔드는 S3로 설정되어 있는 상태입니다.
  2. terraform state push <파일경로> 명령어는 인자로 전달받은 로컬 파일(terraform.tfstate.backup)의 내용을 읽어 들입니다.
  3. 그리고 그 내용을 현재 구성된 원격 백엔드, 즉 S3 버킷의 state 객체에 강제로 밀어 넣고 덮어씁니다(Upload).

결과적으로 텅 비어있던 S3 백엔드에 예전 로컬 환경에서 관리하던 완전한 인프라 상태 정보가 업로드되었습니다. 이제 Terraform은 S3에서 정상적인 상태를 읽어올 수 있으므로, 이후 terraform plan을 실행하면 기존 인프라를 문제없이 인식하게 되는 것입니다.

교훈 및 주의사항

  • Backend 마이그레이션 시 주의: terraform init 실행 중 나오는 State 복사 프롬프트를 주의 깊게 읽고, 기존 인프라를 그대로 가져가야 한다면 반드시 yes를 입력해야 합니다.
  • 백업의 중요성: 로컬에서 작업할 때 생성되는 .tfstate와 .tfstate.backup 파일은 이럴 때를 대비한 훌륭한 백업본입니다. 안전하게 보관해야 합니다.
  • push 명령어 사용 시 주의: terraform state push는 강력한 복구 도구이지만, 원격 상태를 강제로 덮어씌우는 매우 위험한 명령어이기도 합니다. 다수가 협업하는 환경에서 잘못 사용하면 다른 사람의 변경 사항이나 최신 상태를 과거 상태로 덮어버릴 수 있으므로, 복구 목적 외의 일상적인 상황에서는 사용을 피하는 것이 좋습니다.
