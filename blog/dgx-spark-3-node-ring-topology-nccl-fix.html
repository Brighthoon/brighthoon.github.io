DGX Spark 3대 연결 (Ring Topology) 및 NCCL 오류 해결

2026.05.14
5 min read

DGX Spark 2대 연결 하는것 까지는 Connect Two Sparks에 잘 설명 되어있기도 하고, 한글 포스팅도 많아서 문제없이 진행했다. 최근 Connect Three DGX Spark in a Ring Topology튜토리얼도 올라와서, 2대로 하던거 3대로 하면 1.5배 이득이니까 무작정 해봤더니 되지 않았음.

결론부터 말하면, 기존에 설치하던 NCCL이 아닌 별도의 코드를 다운받아 빌드하여 물리적으로 연결되지 않은 NIC끼리 연결하려던것을 방지해줘야했다.

Connect Three DGX Spark in a Ring Topology에서 수행하는 NCCL test의 경우 node0-node1, node1-node2, node2-node0 간의 NCCL만 테스트함. 하지만 실제 모델 학습시 (잘은 모르지만) 기본적으로 연결된 모든 NIC끼리의 통신이 가능한지 테스트를 진행함. 이때 QSFP 스위치가 있다면 상관 없지만, 나처럼 스위치 없이 ring topology 형태로 연결했을경우 각 노드의 포트가 2개밖에 없기 때문에 물리적으로 연결되지 않는 NIC가 생기고, 이로인해 multi-gpu 학습시 아래와 같은 오류가 발생한다.

# IP는 {node n port p IP} 로 대체한거임
# Node 0 
NCCL WARN Call to ibv_modify_qp failed with 110 Connection timed out, on dev rocep1 s0f0:1, curr state INIT, next state RTR, local GID index 3, local GID ::ffff:{node0 Port0 IP}, remote GID ::ffff:{node2 Port0 IP} 

# Node 1 
NCCL WARN Call to ibv_modify_qp failed with 110 Connection timed out, on dev rocep1 s0f0:1, curr state INIT, next state RTR, local GID index 3, local GID ::ffff:{node1 Port0 IP}, remote GID ::ffff:{node0 Port0 IP} 

# Node 2 
NCCL WARN Call to ibv_modify_qp failed with 110 Connection timed out, on dev rocep1s0f1:1, curr state INIT, next state RTR, local GID index 3, local GID ::ffff:{node2 Port1 IP}, remote GID ::ffff:{node1 Port1 IP}

이를 방지하기 위해 이미 누군가가 github에 구현을 해놓았다. Dual Sparks or Sparks via QSFP switch 와 3-node mesh 섹션에 있는 코드를 보면, 3-node mesh 에서는 NVIDIA 레포지토리가 아닌 다른 레포를 사용함.

NVICIA/nccl(v2.29.7-1)과 해당 레포를 비교 하면 두개의 큰 차이점이 있다. nccl_ep의 와 connect.cc가 추가 되었다는건데 여기서 conncet.cc 가 핵심임.

크게 2가지 함수가 추가되었다.

  • ncclIbGidSameSubnet : 두 GID(global Identifier)가 같은 서브넷에 있는지 확인. GID의 마지막 4바이트에서 IP를 추출한 뒤, 설정된 프리픽스 길이(기본 /24)를 마스킹하여 비교.
    • GID 구조체는 아직 어디에 정의되어있는지 확인하지 못함.
  • ncclIbFindDevBySubnet : 장치 선택. 기본으로 설정된 IB가 적합하지 않을경우(e.g 물리적으로 연결되지 않았을경우) 전체 장치 리스트중 서브넷이 일치하는 장치 인덱스를 반환함.

내가 파악한 동작과정은 아래와 같음.

  1. 초기화 및 호출: NCCL이 통신 연결을 설정할 때, 상대방 노드가 가진 모든 GID 정보를 받아 ncclIbFindDevBySubnet을 호출합니다.
  2. 서브넷 마스킹 계산: ncclParamIbSubnetPrefixLen()을 통해 환경 변수(NCCL_IB_SUBNET_PREFIX_LEN)를 읽어와 IPv4 비교 기준을 세웁니다.
  3. 기본 장치 적합성 판단: 예를 들어, 기본 장치가 2개의 NIC을 묶은 상태인데, 그중 하나라도 원격지 서브넷에 닿지 않는다면 성능 저하나 통신 오류가 발생할 수 있으므로 탈락시킵니다.
  4. 전수 조사: 시스템에 장착된 다른 IB(InfiniBand/RoCE) 장치들을 순회하며 ibv_query_gid를 통해 로컬 GID를 가져옵니다.
  5. 매칭 및 교체: 로컬 GID와 원격 GID를 비교하여 서브넷이 일치하는 장치를 발견하면, 기존 defaultDev 설정을 무시하고 새로운 장치로 라우팅 경로를 변경합니다.
  6. 최종 반환: 적절한 장치를 찾으면 해당 장치 번호를, 끝내 찾지 못하면 다시 defaultDev를 반환하여 기존 동작을 유지합니다.

최종적으로 아래와 같은 네트워크/포트 구성 + nccl 재빌드를 통해 3-node 연결 및 학습을 성공하였음.
