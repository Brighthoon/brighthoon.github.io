📝 2026-04-17 개발 기록

🔄 이전 작업 리뷰

  • YOLOv8 커스텀 학습 데이터 준비 및 S3 업로드 로직 점검 완료.
  • 영상 업로드 시 CORS 이슈에 대한 1차 대응 확인.

🏗️ 진행한 작업 및 트러블슈팅

1. 어노테이션 UI 리팩토링 (Tabs 아키텍처 도입)

  • 작업 내용: AdminProblemAnnotate 페이지를 Action Spotting, Hold Segmentation, Pose Overlays 3단계 탭 구조로 분리.
  • 의사결정 근거:
    • 확장성: 기존 단일 페이지 방식은 복잡도가 높아 향후 추가될 다양한 분석 기능을 수용하기 어려움. 논리적 흐름에 따른 모듈화가 필수적.
    • 데이터 무결성: 성공/실패(Success/Fail) 상태에 따른 동적 UI(Zone 컬러 변경)를 구현하여, 향후 AI 학습 시 명확한 클래스 구분이 가능하도록 설계.

2. Hold Segmentation 및 SVG 정밀 시각화

  • 작업 내용: S3 썸네일 기반의 YOLO 포맷(.txt) 오버레이 기능 구현.
  • 의사결정 근거:
    • 리소스 최적화: Web Canvas 에디터를 직접 개발하는 대신 외부 전문 툴(CVAT) 결과를 활용함으로써 개발 속도와 데이터 정밀도를 동시에 확보.
    • Human-in-the-Loop: AI가 생성한 초안을 사람이 검수/승인하는 워크플로우로 자연스럽게 전환하기 위한 기초 구조.
    • 기술적 해결: viewBox와 preserveAspectRatio를 활용해 CSS object-fit: contain 환경에서도 픽셀 오차 없는 정밀 렌더링 구현.

3. 백엔드 데이터 버저닝(Versioning) 전략 수립

  • 작업 내용: 동일 job_type에 대해 version 필드에 따른 레코드 분리 저장 로직 구현.
  • 의사결정 근거:
    • Data Flywheel: AI 모델(yolo-v1)이 생성한 데이터와 사람이 검수한 데이터(human_reviewed)를 분리 보관하여, 향후 고품질 데이터만 추출해 재학습에 활용하는 선순환 구조 구축.

4. 서버리스 Pose Estimation 인프라 설계

  • 작업 내용: ONNX + AWS Lambda (Container Image) + SQS 조합의 아키텍처 설계.
  • 의사결정 근거:
    • 비용 효율성: GPU Triton 서버 상시 가동 비용 부담을 없애기 위해 사용한 만큼만 지불하는 Scale-to-Zero 아키텍처 채택.
    • 안정성: SQS를 통한 트래픽 제어 및 DLQ를 통한 재시도 로직으로 분석 프로세스의 안정성 확보.

5. AI 추론 최적화 (15fps 샘플링 및 선형 보간)

  • 작업 내용: 15fps 다운샘플링 추론 수행 및 프론트엔드 선형 보간(Lerp) 로직 구현.
  • 의사결정 근거:
    • 모델 학습 최적화: 30fps는 데이터 중복성이 높아 시계열 모델(LSTM 등)에서 기울기 소실을 유발함. 학계 표준(SOTA) 수준인 15fps 샘플링으로 학습 효율 증대.
    • 시각적 경험 보완: 15fps로 인한 끊김 현상을 프론트엔드에서 선형 보간(Linear Interpolation) 처리하여 사용자에게는 60fps 수준의 부드러운 시각적 피드백 제공.

[!abstract] Issue 1: SVG 렌더링 좌표 오차

  • 현상: 브라우저의 이미지 렌더링 사이즈와 원본 이미지 사이즈 차이로 인해 YOLO 다각형 좌표가 어긋남.
  • 원인 및 해결: <svg viewBox="0 0 원본너비 원본높이"> 설정을 통해 브라우저 스케일링에 독립적인 절대 좌표 시스템을 구축하여 해결.

[!abstract] Issue 2: S3 이미지 다운로드 CORS 에러

  • 현상: S3에 저장된 썸네일을 브라우저에서 직접 다운로드하거나 Canvas에 로드할 때 보안 정책으로 차단됨.
  • 원인 및 해결: <img> 태그에 crossOrigin="anonymous"를 추가하여 CORS 요청을 명시적으로 처리함으로써 해결.

💡 새롭게 알게 된 것 / 메모

  • Data Flywheel 아키텍처: 단순히 기능을 구현하는 것을 넘어, 데이터가 다시 모델의 성능을 높이는 구조적 설계의 중요성을 체감함.
  • Temporal Stride: 영상 분석 시 무조건 높은 FPS가 좋은 것이 아니라, 동작의 특성에 맞는 적절한 샘플링 레이트(15fps)가 존재함을 확인.

📅 내일 이어서 할 일

  • AWS Lambda에 Docker 기반 ONNX 추론 환경 배포
  • SQS 이벤트 트리거와 백엔드 상태 업데이트 로직 연동 테스트
  • 15fps 보간 로직의 성능 최적화 (프레임 드랍 발생 여부 확인)
